# 採購單編輯規格獨立選購、UI 寬度防裁切與規格標籤精細化改善方案

本方案旨在解決採購單編輯時無法單獨挑選指定規格商品的問題、擴大彈窗寬度與品名欄位以杜絕文字被截斷（`...`），並針對「單一規格」商品優化標籤展示，消除冗餘顯示。

---

> [!IMPORTANT]
> **已確認之關鍵設計決策**
> - **採購單編輯新增商品**：於搜尋結果卡片直接提供**各規格獨立按鈕**（例如 `+ 時尚黑`、`+ 典雅白`），點擊即可單獨加入指定規格；亦保留 `+ 全選規格` 或點擊品名一鍵加入。
> - **UI 尺寸與品名防裁切**：編輯彈窗由原先的 `max-w-4xl` 擴展至寬版 `max-w-6xl`（極大螢幕支援 `2xl:max-w-7xl`），商品名稱欄位擴展至 `min-w-[280px]` 並移除 `max-w-[180px] truncate` 硬性截斷，改採雙行自然換行，並全面巡檢出入庫與網路訂單看板之表格寬度。
> - **單一規格商品展示規則**：系統判定規格為預設「單一規格」或無規格時，**不展開顯示多餘的規格標籤**；若商品具有具體自訂規格名稱（例如「1.6L陶瓷內膽」）或多規格時，仍完整標示。

## 2. 核心功能改造規劃

### A. 採購單編輯：支援單獨加入指定規格
1. **升級 `SearchableProductCombobox` 元件**：
   - 擴充回呼函式簽名為 `onSelect: (product: Product, specification?: string) => void`。
   - 解析商品之規格清單（`parseSpecifications(p.specification)`）。
   - 若商品擁有 **2 種以上規格**：
     - 在搜尋下拉項目底部渲染規格按鈕列：
       - 各別規格按鈕：`+ 規格名`（點擊呼叫 `onSelect(p, spec)`，單獨帶入該規格，不互相干擾）。
       - 全選按鈕：`+ 全部規格`（點擊呼叫 `onSelect(p)`，加入該商品全部規格）。
     - 若點擊商品卡片本體且未指定規格，則依預設行為加入首個規格或全規格。
   - 若為單一規格商品，直接點擊即可加入。
2. **升級 `EditPurchaseOrderModal`**：
   - 更新 `handleAddItem(prod: Product, specification?: string)`：
     - 當指定了 `specification`，僅新增一筆帶有該規格之採購項目。
     - 當未指定且商品有多規格時，才批次加入。

---

### B. UI 尺寸防裁切與寬度全面擴大
1. **`EditPurchaseOrderModal.tsx`（採購單編輯彈窗）**：
   - 彈窗外層容器由 `max-w-4xl`（896px）升級為 `w-full max-w-6xl 2xl:max-w-7xl`。
   - 採購明細表格：
     - 「商品名稱」欄寬設為 `min-w-[280px]`，移除限制寬度的 `max-w-[180px] truncate`，改採 `break-words leading-relaxed`，確保長品名在各裝置皆能完整閱覽。
     - 「規格」欄寬度設為 `min-w-[150px]`，輸入框寬度調配更具彈性。
     - 表格加入外層橫向自適應滾動，保證在小筆電或窄視窗下也不擠壓版面。
2. **連帶全面巡檢其他功能 UI**：
   - **採購進貨核對入庫確認面板 (`Purchases.tsx -> showConfirmPanel`)**：
     - 由 `max-w-5xl` 升級為 `max-w-6xl 2xl:max-w-7xl`，確認品名欄位具備充足展示空間。
   - **網路訂單看板彈窗 (`Home.tsx -> isOrderDashboardOpen`)**：
     - 擴大至 `max-w-6xl 2xl:max-w-7xl`，確保電商長訂單商品名稱不被壓縮。
   - **快速出入庫與購物車清單 (`OutboundCart.tsx` / `StockManage.tsx`)**：
     - 檢查品名顯示，採用 `break-words` 避免 `truncate` 導致長品名只剩前三個字。

---

### C. 規格標籤智慧化展示規則（單一規格不展開）
1. **優化 `ProductSpecStockBadges.tsx`**：
   - 檢查計算結果 `breakdown`：
     - 若 `breakdown.length === 1` 且其規格名稱為 `'單一規格'`、`''` 或 `'預設'`：
       - **判定為非多規格商品，直接返回 `null`**，不渲染任何規格標籤，杜絕版面冗餘。
     - 若 `breakdown.length === 1` 但具有具體的自訂單一規格（如「黑色 1.6L」）：
       - 依照使用者需求保留展示，以標註特定庫存型號。
     - 若 `breakdown.length > 1`（真正的多規格商品，如 S/M/L、黑/白）：
       - 展開所有規格標籤，標註個別數量（庫存為 0 者以淡灰呈現）。

## 3. 測試與驗證計畫
1. **規格獨立新增測試**：
   - 於採購單編輯點擊搜尋框輸入「P950874」，確認下拉項目直接出現「時尚黑」與「典雅白」按鈕。
   - 單獨點擊「時尚黑」，確認採購明細中僅新增 1 筆時尚黑品項，而不會強迫新增全部。
2. **文字截斷與彈窗尺寸驗證**：
   - 開啟採購單編輯，檢視超過 20 字元的長品名（如「SAMPO 2.4GHz 雙子機無線電話機」），確認文字完整可見且自動分行，無任何 `...` 遮擋。
   - 檢驗全螢幕與不同視窗寬度下的彈窗與表格流暢度。
3. **單一規格隱藏檢驗**：
   - 檢視無規格或預設規格商品，確認不再出現「單一規格」標籤。
   - 檢視多規格商品，確認各規格數量完整列出且缺貨規格呈現淡灰。
4. **專案編譯與語法檢查**：
   - 執行 `npm run lint` 與 `npm run build` 驗證零報錯。
